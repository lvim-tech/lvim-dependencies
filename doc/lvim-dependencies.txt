1. INTRODUCTION                                    *lvim-dependencies-intro*

lvim-dependencies manages project dependencies from inside the manifest file,
across five package managers:

  - npm / yarn / pnpm   (package.json)
  - Cargo               (Cargo.toml)
  - Go modules          (go.mod)
  - Composer            (composer.json)
  - pub, Dart/Flutter   (pubspec.yaml)

For each dependency it shows a 3-component virtual text — Declared → Installed |
Latest — each with its own highlight, and lets you install / update (to a chosen
version) / delete via commands or LSP code actions. All network + package-manager
work is async; results are cached (declared / installed / latest / virtual-text)
with configurable TTL, dynamic throttle, retry-with-jitter and a negative cache.

==============================================================================
2. REQUIREMENTS                                *lvim-dependencies-requirements*

  - Neovim >= 0.10
  - `curl` (registry / latest-version lookups)
  - The CLI of each manager you use: `npm`/`yarn`/`pnpm`, `cargo`, `go`,
    `composer`, `dart`/`flutter`. A missing CLI only disables THAT manager.
  - lvim-utils (OPTIONAL) — palette-driven theming of the panels / virtual text.
    Without it the plugin falls back to plain highlight groups.

Run |:checkhealth| lvim-dependencies to verify the above.

==============================================================================
3. SETUP                                            *lvim-dependencies-setup*
>lua
    require("lvim-dependencies").setup({
        -- see |lvim-dependencies-config| for all keys; every field is optional
    })
<
setup() merges your options into the live config, self-themes from the lvim-utils
palette (when present), and installs the autocommands, `:LvimDeps` command and
LSP handlers. It is safe to open a manifest file before or after setup().

==============================================================================
4. COMMANDS                                       *lvim-dependencies-commands*

                                                                   *:LvimDeps*
:LvimDeps {subcommand} [args]
        The single entry command. `{subcommand}` is completed at the prompt
        (core cache commands + the active manifest's manager commands). With no
        argument it prints help.

Core subcommands (always available): >
    install             update [package]     update-direct <package> <version>
    delete [package]    show                 hide
    toggle              cache [type]         clear-declared
    clear-installed     clear-latest         clear-all-caches
    show-registry       show-manager         state
    metrics             help
<
Package operations (install / update / update-direct / delete) and the
virtual-text toggles (show / hide / toggle) act on the dependency under the
cursor in the CURRENT manifest buffer. The same operations are also available
as LSP code actions on the dependency line (|lvim-dependencies-lsp|).

Manager subcommands are contributed by the manager of the current manifest, so
completion only offers what applies to that file; currently the only one is
Cargo's `features <package>` (feature management).

==============================================================================
5. VIRTUAL TEXT                              *lvim-dependencies-virtual-text*

Each dependency line gets a 3-component annotation:

  Declared  →  Installed  |  Latest

rendered with the `groups` highlights (|lvim-dependencies-config|). A spinner
replaces the annotation while an install / update / delete runs on that line.
Colours track the theme (via the lvim-utils palette) and respect a transparent
background.

==============================================================================
6. LSP INTEGRATION                                    *lvim-dependencies-lsp*

The plugin registers a lightweight in-process LSP source, so any client shows:

  - HOVER on a dependency — the package's metadata / available versions.
  - CODE ACTIONS on a dependency — install / update (pick a version) / delete.

Disable it with `lsp = { enabled = false }`.

==============================================================================
7. CONFIGURATION                                   *lvim-dependencies-config*

The live config is `require("lvim-dependencies.config")`; setup() merges your
options into it in place. Top-level keys:

                                                     *lvim-dependencies-opt-managers*
title       info-panel border-title FALLBACK text ("Lvim Dependencies") — used
            when a view passes no title of its own ("LvimDeps Help", …).
title_pos   info-panel border-title alignment: "left" | "center" (default) |
            "right" — layout-independent (float / area / bottom the same).
managers    per-manager on/off switches, keyed by manager name (`pubspec`,
            `cargo`, `npm`, `composer`, `go`): >lua
                managers = { go = { enabled = false } }
<           An opt-OUT — every manager ships enabled and one left out of the
            table stays enabled. A disabled manager is never registered at
            all: its files stop being recognised, no virtual text is drawn
            for them, and its commands, LSP handlers and hover providers are
            not loaded.
groups      highlight group names for the virtual-text components.
ui          panel / virtual-text appearance.
dock        the info panel's dock-stack integration (`dock_stack`, per-layout
            `force` geometry). The panel routes through the shared lvim-utils dock,
            which keys entries by (id, LAYOUT): the base id "lvim-dependencies" is
            the stable identity, so the SAME panel opened in a DIFFERENT layout is a
            SEPARATE entry in that layout's stack — the info panel can be docked in
            float, bottom AND area AT ONCE (one entry per stack, present in multiple
            stacks simultaneously), while re-opening the same (id, layout) re-shows
            the one entry (never a duplicate). Cyclable <Leader>n/p, kill <Leader>x.
lsp         `{ enabled = true }` — hover + code actions.
cache       TTL + negative-cache window for the declared/installed/latest layers.
async       concurrency, dynamic throttle, retry + jitter.
metrics     operation metrics (view via the manager UI).
notify      notification routing/levels.
debug       debug logging.
cargo / npm / composer / go / pubspec
            per-manager overrides (registries, extra CLI flags, …).

Every field is optional; omit the argument to setup() for defaults.

==============================================================================
8. HEALTH                                            *lvim-dependencies-health*

|:checkhealth| lvim-dependencies verifies the Neovim version, `curl`, each
manager's CLI (a missing one disables only that manager), and whether lvim-utils
is available for palette theming.
